# Security Policy

## ⚠️ Important Notice

LibertyCode is **new, actively developed software**. As with any early-stage project, security vulnerabilities may exist. Please read this document carefully before using LibertyCode in sensitive environments.

---

## Supported Versions

Always run the **latest release**. Older versions may contain known vulnerabilities that have since been patched. There are no backported fixes for older versions.

**→ Latest release: https://github.com/Fanatic911/LibertyCode/releases/latest**

---

## Known Risks

### API Key Storage

API keys are encrypted before being written to disk using AES-256-GCM. The encryption key is derived from a machine-specific identifier. This means:

- Keys are **never stored in plain text**
- Keys are **not portable** between machines — if you copy your config to another machine, you will need to re-enter your keys
- The encryption implementation **has not been independently audited**

If you suspect your machine has been compromised, rotate your API keys immediately at your provider's dashboard.

### Shell Command Execution

LibertyCode can execute shell commands on your behalf (via the `run_command` tool or `auto` mode). This is a deliberate feature — but it means:

- In `auto` mode, the agent can run any command without asking
- Always use `ask` or `edits` mode in sensitive or production environments
- Never point LibertyCode at a workspace you don't fully trust
- Review every shell command before approving it in `ask` mode

### AI-Generated Code

LibertyCode generates code using third-party LLM models. AI-generated code:

- May contain bugs, security flaws, or unintended behavior
- Should **always be reviewed** before execution or deployment
- Should **never be deployed** to production without human review

LibertyCode does not validate the safety of code it generates.

### Network Exposure

LibertyCode sends your prompts, file contents, and workspace context to external LLM providers. Be aware:

- Do not include passwords, tokens, or private keys in files you work on with LibertyCode
- Do not send sensitive business data to third-party API providers
- If using Ollama (self-hosted), ensure your Ollama server is not exposed to the public internet (`ollama serve` binds to `127.0.0.1` by default — do not change this unless you know what you are doing)

### Python Package Supply Chain (Linux / macOS)

The Linux and macOS versions install Python packages from PyPI (`rich`, `prompt_toolkit`, `httpx`, `cryptography`). These packages are well-known and widely used, but:

- Always install LibertyCode from the official GitHub releases
- Do not install from unofficial mirrors or third-party sources
- Verify the SHA256 checksum of downloaded releases when available

## Recommendations

| Situation | Recommendation |
|---|---|
| General use | Use `ask` mode — always review before approving |
| Sensitive codebase | Use `ask` mode, review every diff carefully |
| Production environment | Do **not** use `auto` mode |
| Shared machine | Store LibertyCode config in a user-only directory (default) |
| Self-hosted model | Bind Ollama to localhost only |
| API key rotation | Rotate keys if you suspect any compromise |

## Reporting a Vulnerability

If you discover a security vulnerability in LibertyCode, **please do not open a public GitHub issue**.

Report it privately through one of these channels:

- **GitHub Security Advisory:** [Open a private advisory](https://github.com/Fanatic911/LibertyCode/security/advisories/new)
- **Direct contact:** reach the maintainer through GitHub

### What to include in your report

- A clear description of the vulnerability
- Steps to reproduce the issue
- The version of LibertyCode you are using (run `libertycode --version`)
- Your assessment of the potential impact
- Any suggested fix, if you have one

### What to expect

- We will acknowledge your report as quickly as possible
- We will work on a fix and keep you updated on progress
- Once a patch is released, the vulnerability will be disclosed publicly
- Credit will be given to the reporter unless you prefer to remain anonymous

## Scope

This security policy covers the **LibertyCode application** itself. It does not cover:

| Out of scope | Why |
|---|---|
| Third-party LLM providers | Covered by their own security policies |
| PyPI packages LibertyCode depends on | Covered by their own maintainers |
| The OS or environment where LibertyCode runs | Outside our control |
| Code generated by LibertyCode | Responsibility of the developer using it |
| Ollama or other self-hosted model servers | Covered by their own projects |
